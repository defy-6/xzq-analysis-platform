# 智能分析模块（AI 分析）

平台第二大模块：基于平台五类数据（企业关系、人口流动、交通可达性、用地结构、公共服务设施）与引力模型四象限成果，调用 **DeepSeek / 通义千问** 生成厦漳泉都市圈发展状况分析报告，并支持对报告与数据继续追问。

## 模块构成

| 部分 | 位置 | 说明 |
|---|---|---|
| 前端页面 | `apps/web/app/features/ai-analysis/ai-analysis.tsx` | 模型切换、5 个分析主题、流式报告、追问对话 |
| 服务端代理 | `apps/web/worker/index.ts` → `POST /api/ai/chat` | 组装 prompt、多轮 Function Calling（AI 按问题调用查询工具）、转发 LLM API、流式返回；API Key 只存在于服务端 |
| 数据摘要 | `apps/web/scripts/build/build_ai_summary.mjs` → `apps/web/public/data/ai/summary.json` | 摘要基线（约 68KB），各主题切片注入 prompt |
| 查询索引 | `apps/web/scripts/build/build_ai_query_index.mjs` → `apps/web/public/data/ai/query-*.json` | 六个模块的紧凑查询索引（约 8.3MB），供 Function Calling 工具筛选/聚合源数据 |

## Function Calling（AI 按问题查源数据）

AI 回答时若需要摘要中未给出的明细，可自主调用工具查询平台源数据（Worker 端执行筛选/聚合），工具结果优先于摘要、禁止编造。

| 工具 | 作用 |
|---|---|
| `query_enterprise` | 企业投资/分支/专利；`mode=pair`（默认）按无向区县对聚合 TOP（条数+金额），`mode=industry` 按行业/产业链聚合 TOP（适合"企业联系在哪些行业"）；可按关系类型、行业/产业链、区县对、跨市/市内筛选 |
| `query_population` | 人口流动，区县/镇街层级，联系对 TOP 或净流动 |
| `query_transport` | 区县对驾车时间/距离/过路费、区县可达性排名 |
| `query_land` | 区县用地（开发强度、工业/商业/公共服务占比、居住结构） |
| `query_services` | 区县 POI 总量/每万人水平排名、多区县对比（`counties` 逗号分隔，支持"泉州市区"等口语别名 → 自动展开为鲤城区+丰泽区等）、POI 大类/中类明细；`measure`=count/per10k（每万常住人口，公平对比不同规模区县） |
| `query_quadrant` | 引力模型四象限区县对（按象限、跨市/市内） |

工作流：`/api/ai/chat` 收到请求后先做**决策轮**（非流式，模型决定直接回答或调用工具）→ 有工具调用则执行并回填 tool 消息 → **最终轮流式返回**（≤3 轮）。本地 dev 查询索引经 `node:fs` / fetch 自身静态资源加载，生产经 `env.ASSETS` 加载，实例级缓存。

**防"过程性文字无后续"**：部分模型（尤其 DeepSeek-V4 Flash）在多步工具调用中只输出进度/计划文字（如"已获取…现在查询…"）而不给完整回答。处理：
- 系统提示词【工具调用规则】禁止输出过程性文字，要求"要么工具调用、要么最终完整回答"，支持并行发起多个工具调用；
- 决策轮内容若不像完整回答（<200 字或无标题结构），追加为上下文并强制最终轮流式补全；
- `query_enterprise` 提供 `mode=industry` 按行业聚合，避免"只拿到区县对总量、无法按行业拆分"的卡点。

## 数据摘要

摘要聚合粒度对齐分析报告口径——具体到**区县对、镇街、产业门类、POI 中类、用地门类**，包含：

- `overview` 总体概览；`cities` 三市对比（企业/人口/用地/公共服务/交通）
- `counties` 28 区县画像（人口净流动、企业联系、用地细分、服务、交通可达性）
- `topFlows` 关键联系（企业区县对、人口区县对、区县净流入、人口镇街对 TOP）
- `industry` 产业联系（`byChain` 十二类产业链聚合、`byChainCountyPair` 产业链×区县对（跨市 TOP15+市内 TOP8）、`chainByScope` 各产业链跨市/市内条数与占比）
- `quadrant` 引力模型四象限（各象限代表区县对、functionType）
- `transport` 交通可达性（城市对、跨市最快、可达性最差区县）
- `land` 用地（开发强度/工业仓储占比 TOP）；`services` 公共服务（POI 中类相对倍数）
- `keyPairs` **关键区县对画像**（重点跨市 20 对 + 市内 8 对的人口流动、企业条数、交通时间、四象限、两侧用地/POI，含 `flowType` 区分跨市/市内），供模型直接引用、减少数字幻觉

> 分析范围约定：**跨市与市内联系并重**（市内如思明—湖里、芗城—龙文等强联系反映核心城区组织）；产业分析要求落到**具体产业链门类**（农业食品、纺织鞋服与消费品、建材家居、先进装备制造、电子信息与数字等十二类）。

重新生成摘要与查询索引（平台数据更新后）：

```bash
cd apps/web
node scripts/build/build_ai_summary.mjs        # 或 pnpm build:ai-summary（摘要基线）
node scripts/build/build_ai_query_index.mjs    # 或 pnpm build:ai-query-index（查询索引）
pnpm build:ai                                  # 两步一起
```

## Worker API

### 接口一览

| 路由 | 方法 | 作用 |
|---|---|---|
| `/api/ai/models` | GET | 模型注册表 + 每个模型的密钥配置状态（`configured`），前端据此动态渲染模型下拉并提示未配置的厂商 |
| `/api/ai/chat` | POST | LLM 代理：多轮 Function Calling（决策轮 → 执行查询工具 → 流式返回） |
| `/api/ai/check` | POST | 报告质量自检（结构/篇幅/数据引用），返回 `{ok, warnings}`；前端据此触发自动修订 |

### 模型注册表

模型列表集中在 Worker 端 `LLM_REGISTRY`（`worker/index.ts`），新增模型只加一行即可，`/api/ai/models` 与 `/api/ai/chat` 自动生效。当前注册：

| 厂商 | 模型 key | 说明 |
|---|---|---|
| DeepSeek | `deepseek-v4-pro` | V4 Pro · 旗舰（默认） |
| DeepSeek | `deepseek-v4-flash` | V4 Flash · 快速 |
| 通义千问 | `qwen3.6-plus` | 3.6 Plus（默认） |

厂商差异由 Worker 自动处理：

- DeepSeek V4 系列：顶层 `thinking={type:"disabled"}` + `max_tokens=8192`（V4 默认 thinking 且思考 token 计入 max_tokens，**必须用顶层字段**而非 SDK 的 extra_body，否则思考会吃光额度导致 content 为空）；
- 通义千问：顶层 `enable_thinking=0`；
- 统一 `temperature=0.3` 提升稳定性；
- **报告生成**走单次纯摘要流式调用（稳定完整）；**追问对话**开启 Function Calling（决策轮 → 工具 → 流式）。

`POST /api/ai/chat` 请求体：

```jsonc
{
  "provider": "qwen",                 // "qwen" | "deepseek"
  "model": "qwen-plus",               // 可选；模型注册表 key
  "topicId": "border",                // 分析主题；见下方
  "summaryText": "{...}",             // /data/ai/summary.json 内容（前端加载后随请求提交）
  "messages": [{ "role": "user", "content": "请生成分析报告。" }]
}
```

响应为 `text/event-stream`，事件数据形如 `data: {"choices":[{"delta":{"content":"..."}}]}`，结束事件 `data: [DONE]`。

### 分析主题（topicId）

| topicId | 主题 | 对应分析需求 |
|---|---|---|
| `overall` | 都市圈综合研判 | 城市定位、区域分级、交界地区、数据特色四部分一体成文 |
| `positioning` | 城市定位与节点格局 | **定位只能用数据能支撑的词汇**（可用定位词汇表+对应数据路径：综合组织枢纽→企业联系/交通/中心功能；产业节点→**必须指明具体产业链并引用该链条数/金额/跨市占比**；商贸物流/金融商务/科教医疗→对应产业链与用地/POI；边界走廊→跨市流动；交通门户→门户指数；新城/腹地→强度与流动方向）。数据中不存在的维度（高端服务/创新策源/临港/总部经济等）禁用；数据不足如实标注或降级为"功能综合型" |
| `regions` | 成熟区 · 潜力区 · 不及预期区 | **五维度综合评级**（人口/企业/交通/用地设施/四象限仅辅助）；区域单元含**成片区域组团**（厦门组团、泉州环湾组团、漳州东部沿海组团、跨市走廊等），不只单区县/区县对 |
| `border` | 交界毗邻地区 | 边界地区联系形态、两侧分工与差异 |
| `insights` | 数据揭示的特色 | 只有通过数据才能体现的反常识发现 |
| `chat` | 数据问答 | 对话追问（默认） |
| `repair` | 报告修订 | 质量不达标时自动二次修订（前端在 `/api/ai/check` 返回 `ok:false` 时自动触发） |

### 质量自检与自动修订

生成完成后前端调用 `/api/ai/check`（`POST {report}`）做规则化检查：篇幅 ≥800 字、Markdown 章节 ≥2、正文引用具体数字、结论使用「数据：…」佐证。不合格自动调用 `topicId=repair` 让模型按警告重写一次（数据仍必须来自平台数据），失败则保留初版并提示。

### 报告审核闭环（分析稿 → 审核稿）

报告采用**分析稿 / 审核稿**两态（参考城乡融合项目审核闭环：AI 生成 → 人工审核 → 审核版本优先复用）：

- **分析稿**：AI 刚生成的报告（未审核）**自动保存**（`draft` 字段 + 历史版本），刷新或重新打开主题后直接显示已保存的分析稿、**不重新生成**；主题卡片与报告标题旁显示蓝色「**分析稿**」徽标，操作区显示「**编辑审核** → **保存为审核稿**」；
- **审核稿**：点击「编辑审核」进入编辑器逐段修改后「保存为审核稿」生成（绿色「**人工审核稿**」徽标）；**审核稿可继续编辑保存**（保存即更新审核稿，不另起一版）；
- 打开主题时**优先显示审核稿**（审核稿 > 内存分析稿 > 最新历史版本），避免重复生成烧钱——对应参考项目「`reviewed_content.json` 覆盖 content、报告输出优先复用已审核版本」；
- 保存审核稿时同步写入历史版本（source=「审核稿」）；每个主题保留最近 3 个版本（生成/审核稿），可「载入编辑」「查看」「删除」；
- 历史版本与审核稿仅存于浏览器本机，不提交服务器。

### 认可/错误标记（审定结论延续）

报告中的任意段落可**选中后通过浮动标记条**（出现在选区上方，无需回到顶部）标记为「**认可**」或「**错误**」，存入浏览器（`xzq-ai-accepted-v1`）作为该主题的审定结论：

- **标记即高亮**：认可结论在报告中绿色高亮（`aiMarkAccept`），错误结论红色高亮（`aiMarkError`），刷新后从本地恢复；**追问对话区的回答同样可选中标记**（浮动条），标记存入当前主题（自由提问时存 `chat`），并在追问回答中同步高亮；
- 每条结论对应主题，列表显示「认可/错误」类型徽标，可查看、删除；
- 下次**生成报告与追问**时随请求（`acceptedConclusions` 参数，含 `kind` 字段）注入系统提示词：
  - **认可**（`kind:"accept"`）→ 要求 AI **必须延续**（不得矛盾，可深化、补充数据，冲突时说明依据并提示复核）——对应参考项目「审定资料库注入、确定性部分不给 LLM」的模式；
  - **错误**（`kind:"error"`）→ 要求 AI **不得沿用**这些表述，涉及处给出修正说法（以平台数据为准）；
- 实测：注入认可"海沧—龙海是第一核心区县对"+ 错误"漳州西部山区属于成熟协调型组团"后，AI 延续认可结论、未沿用错误说法。

### 表格与地图下载建议

- **表格**：AI 在报告中输出 Markdown 表格（表头/斑马纹/换行均支持）；**报告不生成统计图表（柱状图/折线图/饼图）也不嵌入地图**——多区县/多区县对对比一律用表格呈现；
- **地图下载建议**：报告末尾固定输出「## 地图下载建议」章节，用 Markdown 表格推荐 3-6 张值得下载的地图（列：建议地图｜所在模块｜筛选变量｜推荐口径/说明），每条对应报告中的具体结论；用户照清单到平台对应模块手动筛选变量后导出 PNG：
  - 模块与筛选变量：**企业关系**（联系范围/关系类型/产业链/前N条）、**人口流动**（分析层级/联系范围/起终点/前N条）、**交通可达性**（层级/范围/指标/前N条）、**用地分析**（城市范围/地图指标/定位区县）、**公共服务设施**（城市范围/分类口径/POI功能/比较口径/定位区县）、**联系象限**（联系类型/象限）；
  - 实测示例（border 主题）："海沧—龙海跨市人口流动前30镇街OD图｜人口流动｜分析层级：镇街；联系范围：跨市；起点/终点：海沧区、龙海区；前N条：30｜支撑'角美镇与海沧各街道构成厦漳第一通勤走廊'结论"。

### 追问反哺报告

追问中的有效结论可反哺回报告（报告操作区按钮，需已有追问记录）：

- **「并入追问」**：把最近几轮问答格式化为「## 追问补充」章节追加到报告末尾，保存为新版本（来源标记"追问补充"），零调用成本；
- **「AI 融合」**：把「原报告 + 追问记录」交给模型（`topicId=merge`），融合输出完整新报告——追问结论按主题归入对应章节或新增小节、去掉问答痕迹、冲突处按数据修正，流式生成后保存为新版本（来源标记"AI 融合"）；
- 融合结果与追加结果都作为**新版本**保留（不覆盖原版本/审核稿），可继续编辑或保存为审核稿。

### 追问与报告相悖时的处理（一致性约束）

系统提示词内置【与背景报告的一致性】规则：

- 追问默认与背景报告的结论和数据口径保持一致；
- 若发现背景报告的数字/结论与平台数据或工具查询结果不一致，**不得悄悄改口**：必须明确标注「⚠️ 与背景报告不一致」，先引用原表述，再给出修正后的数据与依据（注明来源：摘要/工具查询），并提示可将修正标记为认可结论或更新审核稿；
- 工具实时查询数据优先于报告旧数据，但差异显式说明；
- 前端对话区检测到「⚠️ / 与背景报告不一致」时显示冲突提示条。
- 实测：背景报告写"海沧—龙海双向 37.6 万"，AI 调用工具核实后明确区分单向（37.6 万）与双向（75.2 万）口径，结论（第一核心）延续、数字显式修正，不悄悄改口。

### 报告风格（系统提示词内置）

- 结论先行，再用具体数据佐证；
- 数据落到产业门类（纺织鞋服、建材、电子信息制造…）、功能类型、用地门类、具体镇街与区县对；
- 所有数字必须直接来自平台数据，严禁编造（优先引用 `keyPairs` 表中的现成数值）；
- **政府报告行文规范**（【行文规范】内置）：语言正式克制、避免口语化夸大；人口流动用「双向流动规模/流入流出规模」表述、全文不出现"净流入/净流出 X 人"净额数字；引力模型结果不写"Ⅰ/Ⅱ/Ⅲ/Ⅳ象限/落入某象限"，改用「高于/低于引力模型预期」「呈成熟协调型/潜在成长型协同格局」等规范用语；结论留有余地、区分数据事实与推断；**报告与追问回答全文不得出现英文变量名/字段名**（topFlows、keyPairs、quadrant 等），数据来源用中文表述（chat 任务提示词已同步强调）；**企业联系必须落到具体行业/产业链（条数+金额）、POI 必须落到中类功能（数量/人均），不得只报总量**（SYSTEM_BASE 与 chat 任务均内置）。

> **为什么不用"净流入/净流出"**：人口流动数据为 **2022 年 6 月手机信令到访数据**，原始口径（月总量/单日到访量/时段平均值）尚不明确。"净流入/净流出"是对时间口径敏感的净额推断，口径不明时不能成立，因此报告只表述「双向流动规模」「流入/流出规模」等不依赖时间口径的相对量，流动方向仅作定性表述。该约束同时写入 Worker 的【口径说明】与 `docs/数据资产清单.md`。

## API Key 配置

Key 只存服务端，浏览器不接触：

- **本地开发**：`vite.config.ts` 已把系统环境变量透传给本地 Worker——在系统（用户级）环境变量中设置：
  - 通义千问：`DASHSCOPE_API_KEY`（已配置）
  - DeepSeek：`DEEPSEEK_API_KEY`（已配置；注意：修改环境变量后需重新打开终端/启动进程才会生效）
  - 配置后前端 `/api/ai/models` 会显示对应厂商 `configured: true`，未配置的厂商在页面模型切换处有提示。
- **生产部署**：在部署平台（Cloudflare 等）为 Worker 配置同名环境变量/Secret `DASHSCOPE_API_KEY`、`DEEPSEEK_API_KEY`。

### 字数预设

- 点击「生成报告 / 重新生成」时**先弹出字数选择**（不再一点击就生成）：预设档位 600-1000 / 1000-1500 / 1500-2500 / 2500-4000 / 4000-6000 字，或自定义下限—上限；
- 选择随请求 `wordRange` 字段提交，Worker 注入系统提示词【篇幅要求】（正文字数、达到下限即可收尾、不足用区县/镇街/行业细节补足）；
- 选择保存在浏览器（`xzq-ai-wordrange-v1`），下次打开默认选中上次档位；打开主题自动生成（无历史内容）时直接用当前预设不弹窗；
- 说明：AI 对字数的把握存在 ±30% 左右偏差（deepseek-v4-flash 倾向写长），未做硬截断以免破坏章节结构。
